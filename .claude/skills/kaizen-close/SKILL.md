# Kaizen Close — 継続的改善の締めワークフロー

本プロジェクトは「継続的改善（kaizen）」を開発ルールに掲げており、**タスク完了報告の前に、得られた知見を必ずどこかに反映する**。本スキルはその標準手順。

## 適用タイミング（When to Use）

- 任意のタスクを完了し、ユーザーに「完了しました」と報告する直前
- セッション内で新たな罠・回避策・工夫を発見した時
- ユーザーから新たな好み・指示が与えられた時

## 手順（How It Works）

### Step 1: 自問

以下のチェックリストを声に出して（=出力に書いて）確認する：

- [ ] 今回のタスクで詰まった点はあったか？
- [ ] 回避策・工夫したことはあるか？
- [ ] ユーザーから新たに学んだ好み・スタイルはあるか？
- [ ] 設計書 / CLAUDE.md / README に書かれていない暗黙知が増えたか？
- [ ] 次セッションが同じ罠を踏みそうか？

ひとつでも YES なら Step 2 に進む。全部 NO なら本スキル終了。

### Step 2: 反映先を選ぶ

| 種類 | 反映先 |
|---|---|
| Claude Code が次回踏みそうな罠・規約・ビルド手順 | [CLAUDE.md](../../../CLAUDE.md) |
| 人間の読者向けの永続情報・セットアップ手順 | [README.md](../../../README.md) |
| 設計判断の経緯・なぜそうしたか | 計画ファイル `~/.claude/plans/` または `Docs/` |
| ユーザーの好み・セッション横断のスタイル | メモリ（`~/.claude/projects/.../memory/`） |
| 再発を機械的に防げる事象 | `.gitignore` / CMake / `.claude/settings.json` 等の設定 |
| 繰り返し起こるワークフロー | 新規スキル `.claude/skills/<name>/SKILL.md` |
| 繰り返し必要な専門レビュー | 新規エージェント `.claude/agents/<name>.md` |

### Step 3: 反映を実行

選んだ反映先に追記・編集する。**重複を避け、既存内容と整合させる**こと。

### Step 4: 完了報告

報告の末尾に「**継続的改善**：<反映内容の 1 行サマリ>」を含める。
反映するものが無かった場合は「**継続的改善**：今回の追加学習なし」と明示。

## やってはいけないこと（Must Never）

- 反映ステップをスキップして完了報告する
- 「とりあえず CLAUDE.md に書く」だけで終わらず、本当にそこが最適な場所かを Step 2 で選び直す
- 既存記述と矛盾する内容を追記する（必要なら旧記述を更新する）
- 一過性の作業ログ（コミットメッセージで十分なもの）を CLAUDE.md / README に残す

## 例（Example）

```
タスク : Task 1 完了
気付き : macOS 14+ で Qt 6.7 が AGL 不在でリンク不可、Qt 6.8+ への切替が必須

反映先選定：
- 次セッションも同じ罠を踏む可能性大 → CLAUDE.md の「Qt バージョンの罠」セクション
- 人間の読者向けの前提条件 → README.md の「前提」セクション
- 同じ症状が再発した時の専用解決手順 → cmake-build-resolver エージェント

実行：上記 3 箇所を更新

完了報告末尾：
継続的改善：CLAUDE.md と README に AGL 罠を追記、cmake-build-resolver エージェントを新設
```
